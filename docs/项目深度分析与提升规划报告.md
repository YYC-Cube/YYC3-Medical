## 1. 执行摘要

**YYC³-Med 是一个**定位宏大、技术栈先进、但**实质处于"高保真原型阶段"的医疗 AI 智能诊疗前端系统**。

- ✅ **架构先进**：Next.js 16 (App Router) + React 18.3 + TypeScript 严格模式 + Tailwind 3 + Zustand + Radix UI/shadcn，**纯静态导出**（`output: 'export'`）部署至 GitHub Pages。
- ✅ **规模可观**：654 个 TS/TSX 文件、122k LOC、112 个页面、439 个组件、29 个领域服务、19 个自定义 Hook、4 语言 i18n。
- ⚠️ **现状脱节**：当前工作区有 **15 个已跟踪文件被本地删除但未提交**，导致 `next build` 在干净检出时**立即失败**。`AGENTS.md` 中"build 全绿"的描述与实测不符（详见 §3）。
- 🔴 **业务空心化**：全部 29 个 service 为**前端 mock / stub**，无任何真实后端调用；`prisma/schema.prisma` 描述的 MySQL 后端**完全未接入**；`lib/auth/jwt.ts`、`lib/db.ts` 均为占位代码。
- 🔴 **测试覆盖严重不足**：9 个测试文件、141 个用例，阈值仅 **1%**，对照 439 个组件 / 122k LOC 属于"几乎裸奔"。
- 🟡 **合规距离遥远**：作为一个面向"医疗器械辅助诊断"的产品，距离 NMPA 三类医疗器械注册、IEC 62304 / ISO 14971 / ISO 13485 等基础合规要求尚有数量级的差距。

**核心结论**：项目**技术形态像产品、业务实质像 Demo**。要在 12–18 个月内演进为可商用、可申报的医疗器械 AI 软件SaMD（Software as a Medical Device），需要按 §11 的 5 阶段路线图执行，预计投入 **8–15 人月（核心团队）+ ¥300 万–¥1,200 万合规与临床试验预算**。

## 3. 🔴 关键阻断问题（P0，必须立即处理）

以下问题按优先级排序，每一项都会**直接阻断 CI / 部署 / 商用**。

### P0-1：`components/ui/form.tsx` 缺失，构建必失败

- **现象**：`components/ui/index.ts:95` 仍 `export ... from "./form"`，但工作区中 `form.tsx` 已被删除（git 显示 `D components/ui/form.tsx`，HEAD 中存在该文件 213 行）。
- **影响**：
  - `next build` 在 TypeScript 阶段失败：`Type error: Cannot find module './form'`。
  - `tsc --noEmit` 报 1 错误。
  - GitHub Actions `ci.yml` 的 `pnpm build` 步骤**必然失败**。
- **修复**：`git checkout HEAD -- components/ui/form.tsx`（恢复 213 行 shadcn Form 实现），或删除 `index.ts:95` 该行导出（若确认全项目不再使用 Form）。**建议恢复**，因 react-hook-form 已在依赖中。
- **耗时**：5 分钟。

### P0-2：`next.config.mjs` 硬编码绝对路径

```js
turbopack: {
  root: '/Users/yanyu/YYC-Cube/YYC3-Medical',  // 🔴 硬编码
},
```

- **影响**：CI / 任何非该开发者的机器上 `next build` / `next dev` 行为异常或失败。
- **修复**：删除 `turbopack.root` 配置（让 Next.js 使用默认 `process.cwd()`）。
- **耗时**：1 分钟。

### P0-3：本地 pnpm workspace 被 `/Users/yanyu/pnpm-workspace.yaml` 劫持

- **现象**：执行 `pnpm <任何命令>` 均报 `EACCES: permission denied, mkdir '/Volumes/Development'`。
- **根因**：父目录 `/Users/yanyu/pnpm-workspace.yaml` 将工作区根提升至 `/Users/yanyu`，pnpm 试图写入不存在的 `/Volumes/Development`。
- **影响**：开发者**本地无法运行任何 `pnpm` 脚本**（实测 `pnpm type-check` / `pnpm lint` / `pnpm test` / `pnpm build` 全部失败）；必须用 `npx` 或 `pnpm --ignore-workspace`。
- **修复（开发者侧）**：删除或修正 `/Users/yanyu/pnpm-workspace.yaml`，或统一在项目内使用 `pnpm <cmd> --ignore-workspace`。CI 不受影响（CI 在干净的 ubuntu runner 上）。
- **耗时**：5 分钟。

### P0-4：14 个本地删除文件需明确处置

除 `form.tsx` 外，还有 14 个被本地删除但未提交的文件，包括：

## 6. 安全与合规现状

### 6.1 当前安全态势

| 项         | 现状                                                                                                            | 风险                                                  |
| ---------- | --------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| 鉴权       | 前端 Zustand `useAuthStore`（persist 到 localStorage），`lib/auth/jwt.ts` 用 `jose` 做客户端验证                | 🔴 客户端验签**不能作为安全边界**，任何鉴权都可被绕过 |
| 密钥管理   | `JWT_SECRET`、`DEEPSEEK_API_KEY` 通过 env 注入，但静态导出无服务端                                              | 🔴 API Key 暴露风险（若误用 `NEXT_PUBLIC_`）          |
| CSRF / XSS | 无服务端 → 无 CSRF；React 默认转义 → XSS 风险低                                                                 | 🟢                                                    |
| 传输加密   | GitHub Pages 强制 HTTPS                                                                                         | 🟢                                                    |
| 审计日志   | 全部 mock                                                                                                       | 🔴 不可用于合规                                       |
| 数据加密   | 患者数据 mock，未涉及真实 PHI                                                                                   | 🟡 一旦接入真实数据需加密 at-rest/in-transit          |
| 依赖漏洞   | `npm audit` 无法本地运行（无 package-lock）；`audit.yml` CI 跑 `pnpm audit --prod --audit-level=high`（非阻断） | 🟡                                                    |

## 7. 性能与体积分析

### 7.1 构建产物（旧 `out/`，23 MB）

- 总 JS：**8.6 MB**（未压缩）/ 约 2 MB gzip。
- 单 chunk 最大：**370 KB × 5 个**（未压缩），首屏可能加载 1 个 370 KB chunk（gzip ≈ 120 KB）。
- 体积偏大主因：
  1. `three` + `@react-three/fiber` + `d3` + `recharts` 多套可视化库并存。
  2. `@elastic/elasticsearch` 被依赖但**未使用**（应剔除）。
  3. 仅 19 处 `dynamic()` / `React.lazy`，**代码分割不足**。
  4. 112 个页面静态预渲染，但共享 chunk 切分策略保守。

### 7.2 性能优化建议

- 移除未用依赖：`@elastic/elasticsearch`、`react-window`（如未用）、`react-resizable-panels`（如未用）。
- 对 `three` / d3 / 大型业务组件统一走 `next/dynamic` 懒加载。
- 启用 Next 16 的 `optimizePackageImports`（已部分启用 lucide/recharts，可扩展）。
- 引入 bundle analyzer（`ANALYZE=true` 已支持），每月监控。
